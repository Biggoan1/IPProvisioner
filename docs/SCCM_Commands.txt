    Setting type : File

Same clause style as 1.0.1, with the expected version raised from 1.0.1.0 to 1.0.2.0. The
single clause implements "the file exists AND its version is >= 1.0.2.0": a version
comparison cannot be satisfied when the file is absent, so a missing exe evaluates as
not-installed. The rationale for using the exe's FileVersion rather than the ARP
DisplayVersion is unchanged and documented in PACKAGING_NOTES.txt.

Equivalent rebuild of the clause in PowerShell:

$clause = New-CMDetectionClauseFile `
    -Path     'C:\Program Files\IPProvisioner' `
    -FileName 'IPProvisioner.exe' `
    -Value `
    -PropertyType       Version `
    -ExpressionOperator GreaterEquals `
    -ExpectedValue      '1.0.2.0' `
    -Is64Bit

------------------------------------------------------------------
Import-Module 'C:\Program Files (x86)\Microsoft Configuration Manager\AdminConsole\bin\ConfigurationManager.psd1'
Set-Location 'FU1:\'

Set-CMApplication -Name 'IP Provisioner' -SoftwareVersion '1.0.2'

Set-CMScriptDeploymentType -ApplicationName 'IP Provisioner' `
    -DeploymentTypeName 'IP Provisioner 1.0.1 (Script)' `
    -ContentLocation '\\sccm1\Sources\IP Provisioner 1.0.2\Content'

# Add the new clause FIRST, then remove the old one, so the DT is never left with zero
# detection clauses. Both clauses coexist (ANDed) for the duration of one revision.
$clause = New-CMDetectionClauseFile -Path 'C:\Program Files\IPProvisioner' `
    -FileName 'IPProvisioner.exe' -Value `
    -PropertyType Version -ExpressionOperator GreaterEquals -ExpectedValue '1.0.2.0' -Is64Bit
Set-CMScriptDeploymentType -ApplicationName 'IP Provisioner' `
    -DeploymentTypeName 'IP Provisioner 1.0.1 (Script)' -AddDetectionClause $clause

# -RemoveDetectionClause takes the clause's SETTING LOGICAL NAME (e.g. File_<guid>), which is
# only visible in the DT's SDMPackageXML. The 1.0.1 clause was File_48519253-df9b-48ff-b4c0-1f97fc0e81b4.
Set-CMScriptDeploymentType -ApplicationName 'IP Provisioner' `
    -DeploymentTypeName 'IP Provisioner 1.0.1 (Script)' `
    -RemoveDetectionClause 'File_48519253-df9b-48ff-b4c0-1f97fc0e81b4'

Set-CMScriptDeploymentType -ApplicationName 'IP Provisioner' `
    -DeploymentTypeName 'IP Provisioner 1.0.1 (Script)' -NewName 'IP Provisioner 1.0.2 (Script)'

Set-CMApplication -Name 'IP Provisioner' `
    -IconLocationFile '\\sccm1\Sources\IP Provisioner 1.0.2\Icons\IPProvisioner.png'

    -DeploymentTypeName 'IP Provisioner 1.0.2 (Script)'

$dt   = Get-CMDeploymentType -ApplicationName 'IP Provisioner'

    -UserInteractionMode      Hidden `

$clause = New-CMDetectionClauseFile -Path 'C:\Program Files\IPProvisioner' `

    -Name             'IP Provisioner' `
    -CollectionName   'IP Provisioner - Test' `
    -DeployAction     Install `
    -DeployPurpose    Available `
    -UserNotification DisplaySoftwareCenterOnly `

WHY THINGS LOOK THE WAY THEY DO
-------------------------------
2026-07-29  1.0.2 update. Only the detection constant moved (1.0.1.0 -> 1.0.2.0) and the
            content was replaced. The build's functional change (the adapter picker now
            excludes Wi-Fi/cellular NICs) is entirely inside the exe and has no packaging
            impact. IPProvisioner-Install.ps1 is byte-identical to the 1.0.1 copy apart
            from its Authenticode signature block (it was re-signed with the new build).
2026-07-29  1.0.2 update. New source folder D:\Sources\IP Provisioner 1.0.2\ rather than
            overwriting 1.0.1's, matching the convention 1.0.1 established: each version
            keeps its own folder so rollback is a ContentLocation change plus a detection
            constant change, with no file restore.
2026-07-29  1.0.2 update. Clause replacement is add-then-remove, not remove-then-add, so
            the DT never exists with zero detection clauses. Cost is one intermediate
            revision where both clauses are ANDed - harmless because a client satisfying
            >= 1.0.2.0 also satisfies >= 1.0.1.0.
2026-07-29  Updated in place on the existing application (same CI_UniqueID, new revision)
            rather than creating a second app, so no supersedence is involved and the
            existing Available deployment needed no changes.
2026-07-29  Cosmetic leftover, still present: the DT's SDMPackageXML carries an inert
            <DetectionScript> element inside <CustomData> alongside DetectionMethod=Enhanced,
            left over from the 1.0.0 script detection. Set-CMScriptDeploymentType does not
            scrub it. Read Installer.DetectAction (Provider=Local, single MethodBody arg)
            to verify detection - CustomData will mislead you.
2026-07-29  Note that Update-CMDistributionPoint bumps the app revision and mints a new DT
            ContentId, so every ID recorded above changes again on the next redistribute.
            Capture IDs after the redistribute, not before.
2026-07-29  1.0.1 update. Detection changed from a file-existence SCRIPT to a native
            File System clause comparing IPProvisioner.exe Version. Chosen over the
            registry DisplayVersion rule because the ARP DisplayVersion is copied from the
            exe at install time (and defaults to '1.0.0.0' if that read fails), so the
            binary is the more reliable source.
2026-07-29  1.0.1 update. Content moved into a Content\ subfolder so the deployment type
            content holds ONLY IPProvisioner.exe + IPProvisioner-Install.ps1.
2026-07-29  Deployed Available (not Required) per request - this is a manual test ring.
2026-07-29  Max run time is 15 min because that is the SCCM cmdlet floor, not because the
            install is slow (it takes seconds).
